# Stage 2 Control Bridge Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Convert the validated station ShotScript and real Blender scene into per-shot prompts, first/last frames, proxy MP4s, and a hash-addressed backend-neutral control bundle without inventing upload URLs or API results.

**Architecture:** A pure-Python prompt compiler produces plain, cinematic, and time-segmented text from each validated `Shot`. A host-side control exporter invokes the installed Blender executable to reopen the real `.blend`, render six boundary PNGs and three per-shot H.264 clips, then records their actual byte sizes and SHA-256 hashes in `control_bundle.json`. Backend submission remains blocked until local assets have real HTTP(S) URLs.

**Tech Stack:** Python 3.12 standard library; existing ShotScript dataclasses; Blender 5.1.2 at `D:\blender\blender.exe`; Eevee; Blender-bundled FFmpeg; Pillow for inspection tests; unittest.

---

## Evidence boundary

- Prompt unit tests prove deterministic local compilation only.
- PNG and MP4 acceptance requires actual Blender subprocesses and non-empty files.
- File hashes must be computed from the generated bytes, not copied from expected fixtures.
- The bundle must retain local paths and `submission_ready: false`; it must not contain example domains, fake upload URLs, task IDs, model responses, or generated-video claims.
- No external API or server/GPU is used in this stage.
