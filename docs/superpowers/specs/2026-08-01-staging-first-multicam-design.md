# 人物/物体优先的三阶段多机位导演设计

日期：2026-08-01  
状态：用户已批准实施

## 目标

在现有独立 `director-multicam` 页面前增加人物/物体轨迹阶段，形成清晰的三步流程：

1. 编辑并批准人物/物体 K0–K4；
2. DeepSeek 读取已批准轨迹，规划并批准三台摄像机；
3. Blender 渲染三路完整 Proxy，人工观看并批准。

旧 `director-loop`、已有 station P1/M1 和既有证据目录保持不变。

## 数据与门控

- 每个轨迹版本使用不可覆盖目录 `staging/S1`、`S2`……，保存严格 `TrajectoryInstruction` 和哈希记录。
- 初始 S1 由 ShotScript 自动产生，页面自动显示人物 K0–K4；不要求用户先点击初始化。
- 允许 `target.type=actor` 和 `target.type=object`。首版页面编辑已有轨迹，不增加资产建模器；新增道具轨迹使用“添加物体”按钮，默认 K0–K4 静止在画面中心。
- 只有人工批准的 staging 版本可调用 DeepSeek。LLM scene context 读取批准后的点，不读取未批准草稿。
- 保存新人物/物体版本会清空当前 plan/plan approval 和当前 iteration 指针，但历史目录与已有 M1 字节不删除。
- 摄像机规划或轨迹改变不会反向修改人物/物体轨迹。
- Render job 必须绑定 approved staging hash、approved plan hash、actor/object trajectory 和 camera bundle。

## 简洁前端

页面只显示三张编号卡片：

1. “人物与物体”：一个二维轨迹画布、目标下拉框、K0–K4、动作短语、添加物体、保存、批准。
2. “三台摄像机”：职责摘要、摄像机/K 帧选择、同一画布上的摄像机点、批准、渲染。
3. “查看结果”：完整参考视频和三路同步视频、自动指标摘要、批准 Proxy。

高级 JSON 默认不显示。每张卡底部放一行灰色小字说明；按钮在前置门未通过时禁用。已有 `author` 输入框统一用于三道人工批准。

三张卡片位于同一 URL，并作为顺序向导工作：批准第 1 步后自动折叠并滚动到第 2 步；批准第 2 步后自动进入摄像机编辑/渲染；渲染成功后自动进入第 3 步并加载三路视频。用户可以展开上一步查看，但修改已批准内容必须保存为新版本，后端随即使当前下游指针失效。刷新页面后根据 workspace state 恢复到第一个未完成步骤。

## 局部修改规则

- 选择“从 K2 修改”时，K0–K1 只读；轨迹点击仅允许 K2–K4。
- 保存的人物/物体轨迹就是完整 K0–K4，不依赖 Prompt 猜测。
- 后端对冻结前缀与基础版本逐点比较，任何前缀改动都拒绝。
- 人物/物体轨迹变化后重新生成完整摄像机方案；后续可扩展为摄像机 suffix replan，但本次不引入隐式合并。

## 错误与真实性

- schema、身份、K/t 顺序、坐标范围、冻结前缀或哈希错误均返回明确错误，不自动修补。
- DeepSeek 每次按钮操作仍是一调用、零重试。
- 自动评估仅报告同步、可见性、角度和碰撞；人工构图始终需用户批准。

## 验收

- 新工作区自动有 S1，未批准 S1 不能创建 plan。
- 保存并批准 S2 后，DeepSeek context 与 Blender job 都绑定 S2。
- 修改 K2 时 K0–K1 后端不可变。
- 新页面三个阶段清晰、说明文字存在，旧页面不变。
- 真实 Blender 集成仍输出三路 15 帧完整 station 视频。
